# API Reference

Base URL (local): `http://localhost:8000`
Interactive docs (auto-generated by FastAPI): `http://localhost:8000/docs`

All requests and responses use JSON. Errors use `application/problem+json` ([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457)).

---

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/v1/orders/score` | Score one order and return a decision |
| `GET` | `/v1/holds` | List orders currently held for review |
| `POST` | `/v1/holds/{order_id}/resolve` | Record a reviewer's final decision |
| `GET` | `/v1/audit/{audit_id}` | Fetch one audit entry |
| `GET` | `/healthz` | Liveness check |
| `GET` | `/readyz` | Readiness check (models loaded, Redis reachable) |

## `POST /v1/orders/score`

### Headers

| Header | Required | Description |
|---|---|---|
| `Content-Type` | yes | `application/json` |
| `Idempotency-Key` | yes | Unique string per logical request. Retrying with the same key + same body returns the original response. |

### Request body

```json
{
  "order_id": "1001",
  "amount": 129.99,
  "currency": "USD",
  "timestamp": "2026-09-30T10:15:00Z",
  "customer": {
    "account_id": "acc_42",
    "account_age_days": 3,
    "email_domain": "gmail.com"
  },
  "device": {
    "fingerprint": "fp_abc123",
    "ip": "203.0.113.7",
    "type": "mobile"
  },
  "card": {
    "network": "visa",
    "type": "debit"
  },
  "merchant": {
    "merchant_id": "m_9",
    "domain": "cheap-brands-outlet.shop",
    "domain_age_days": 12,
    "rating": 2.9,
    "refund_rate": 0.21
  },
  "items": [
    {
      "sku": "S1",
      "title": "Original Nike Air Max 1:1 quality",
      "description": "same as store, cheap",
      "price": 19.99,
      "category": "footwear"
    }
  ],
  "session": {
    "clicks_last_minute": 42,
    "checkout_seconds": 6
  }
}
```

### Field reference

| Field | Type | Required | Notes |
|---|---|---|---|
| `order_id` | string | yes | Your order identifier |
| `amount` | number > 0 | yes | Order total |
| `currency` | string (ISO 4217) | yes | e.g. `USD`, `INR` |
| `timestamp` | string (ISO 8601) | no | Defaults to server time |
| `customer.account_id` | string | yes | |
| `customer.account_age_days` | integer >= 0 | yes | |
| `customer.email_domain` | string | no | Used as a model feature |
| `device.fingerprint` | string | yes | Used for velocity counters |
| `device.ip` | string | yes | IPv4/IPv6; stored hashed |
| `device.type` | `desktop` \| `mobile` \| `tablet` | no | |
| `card.network` / `card.type` | string | no | Model features |
| `merchant.*` | object | yes | Used by merchant scorer |
| `items[]` | array (1–50) | yes | Each needs `sku`, `title`, `price` |
| `session.clicks_last_minute` | integer | no | Heuristic input |
| `session.checkout_seconds` | number | no | Heuristic input |

### Success response: `200 OK`

```json
{
  "order_id": "1001",
  "decision": "HOLD",
  "trust_score": 0.31,
  "scores": { "merchant": 0.22, "catalog": 0.18, "behavioral": 0.47 },
  "reason_codes": ["NEW_MERCHANT_DOMAIN", "COUNTERFEIT_LISTING_SIMILARITY", "FAST_CHECKOUT"],
  "degraded": false,
  "latency_ms": 41.7,
  "audit_id": "a_000123"
}
```

| Field | Description |
|---|---|
| `decision` | `APPROVE`, `STEP_UP`, or `HOLD` |
| `trust_score` | 0–1, higher is safer. `null` if all scorers failed |
| `scores` | Per-scorer scores. A value is `null` if that scorer timed out/failed |
| `reason_codes` | Human-readable-ish codes explaining the decision |
| `degraded` | `true` if any scorer was unavailable (decision will never be `APPROVE`) |
| `latency_ms` | Server-side processing time |
| `audit_id` | Reference to the audit log entry |

### Reason codes (initial set)

| Code | Source |
|---|---|
| `NEW_MERCHANT_DOMAIN` | merchant |
| `LOW_MERCHANT_RATING` | merchant |
| `HIGH_REFUND_RATE` | merchant |
| `COUNTERFEIT_LISTING_SIMILARITY` | catalog |
| `PRICE_TOO_LOW_FOR_BRAND` | catalog |
| `HIGH_DEVICE_VELOCITY` | behavioral |
| `MANY_IPS_FOR_ACCOUNT` | behavioral |
| `FAST_CHECKOUT` | behavioral |
| `MODEL_HIGH_FRAUD_PROB` | behavioral |
| `VETO_LOW_SCORE` | decision |
| `DEGRADED_MODE` | decision |

### Decision meanings

| Decision | What your checkout should do |
|---|---|
| `APPROVE` | Proceed to payment |
| `STEP_UP` | Trigger 2FA / OTP / extra verification, then proceed if passed |
| `HOLD` | Do not charge; the order appears in `/v1/holds` for review |

## `GET /v1/holds`

Returns held orders, newest first.

Query params: `limit` (default 50, max 200), `cursor` (pagination).

```json
{
  "items": [
    { "order_id": "1001", "trust_score": 0.31, "reason_codes": ["..."], "created_at": "2026-09-30T10:15:00Z", "status": "pending" }
  ],
  "next_cursor": null
}
```

## `POST /v1/holds/{order_id}/resolve`

```json
{ "resolution": "confirmed_fraud", "reviewer": "hari", "notes": "optional" }
```
`resolution` is one of `confirmed_fraud`, `legitimate`. These labels are the seed for the future retraining feedback loop.

## `GET /v1/audit/{audit_id}`

Returns the stored entry, including `prev_hash` and `entry_hash`.

## `GET /healthz` / `GET /readyz`

- `/healthz` → `200 {"status":"ok"}` if the process is up.
- `/readyz` → `200` only if the model and FAISS index are loaded and Redis responds; otherwise `503`.

## Errors (RFC 9457)

Content type: `application/problem+json`

```json
{
  "type": "https://trustshop.example/problems/validation-error",
  "title": "Invalid request body",
  "status": 422,
  "detail": "amount must be greater than 0",
  "instance": "/v1/orders/score",
  "errors": [ { "field": "amount", "message": "must be > 0" } ]
}
```

| Status | When |
|---|---|
| `400` | Missing `Idempotency-Key` |
| `409` | Same `Idempotency-Key` reused with a different body |
| `422` | Payload failed validation |
| `429` | Rate limit exceeded (if enabled) |
| `503` | Service not ready (model not loaded) |

> The scoring endpoint intentionally does **not** return `5xx` when a scorer fails; it returns `200` with `degraded: true` and a safe decision.

---

## Idempotency behavior

1. First request with key `K`: processed, response stored in Redis for 24 h.
2. Repeat with key `K` and identical body: stored response returned, header `Idempotent-Replay: true`.
3. Repeat with key `K` and different body: `409`.

Reference: [Stripe on idempotency](https://stripe.com/blog/idempotency).
