# API Reference

Base URL (local): `http://localhost:8000`
Interactive docs (auto-generated by FastAPI): `http://localhost:8000/docs`

JSON in, JSON out. Errors use `application/problem+json` ([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457)).
*Acme Footwear is a fictional brand used in all examples.*

---

## Endpoints

| Method | Path | Auth | Purpose |
|---|---|---|---|
| `POST` | `/v1/checks` | none (rate limited) | Check a seller's number / message / link / payment details |
| `GET` | `/v1/checks/{check_id}` | none | Fetch a stored check result (summary only) |
| `POST` | `/v1/reports` | none (rate limited) | Report a number, domain, or payment ID as suspicious |
| `GET` | `/v1/brands` | none | List brands in the registry |
| `GET` | `/v1/brands/{slug}` | none | A brand's official channels, with sources and verification dates |
| `POST` / `PUT` | `/v1/admin/brands[/{slug}]` | `X-API-Key` | Create or update registry entries |
| `GET` | `/v1/admin/reports` | `X-API-Key` | Review community reports |
| `GET` | `/healthz` | none | Liveness |
| `GET` | `/readyz` | none | Readiness (registry DB reachable, model loaded) |

## `POST /v1/checks`

### Request body

```json
{
  "claimed_brand": "Acme Footwear",
  "phone_number": "+91 98765 43210",
  "message_text": "Special offer today only! 70% off. Pay advance on this number to confirm.",
  "urls": ["https://acmefootwear-outlet.shop/deal"],
  "payment": {
    "upi_id": "9876543210@ybl",
    "display_name": "Rakesh K",
    "amount": 1499
  },
  "language": "en"
}
```

### Field reference

| Field | Type | Required | Notes |
|---|---|---|---|
| `claimed_brand` | string | no | Brand the seller claims to be. If omitted, the system tries to detect it from the text and domains |
| `phone_number` | string | at least one of these four | Any format. Normalized to E.164 (default region IN) |
| `message_text` | string (max 5,000 chars) | | Pasted chat. Phones, links, and payment IDs inside are extracted automatically |
| `urls` | string[] (max 5) | | Links the seller sent |
| `payment.upi_id` | string | | e.g. `name@handle` |
| `payment.display_name` | string | no | The **name your UPI app shows before you confirm payment**. Greatly improves the payment check |
| `payment.amount` | number | no | Used only for context |
| `language` | `en` \| `ml` \| `hi` | no | Language of the explanation. Default `en`, falls back to English if a translation is missing |

At least one of `phone_number`, `message_text`, `urls`, or `payment.upi_id` is required.

### Success response: `200 OK`

```json
{
  "check_id": "c_000123",
  "verdict": "LIKELY_SCAM",
  "risk_score": 0.91,
  "brand": {
    "claimed": "Acme Footwear",
    "in_registry": true,
    "registry_verified_on": "2026-10-01",
    "match": { "phone": false, "domain": false, "payment": false }
  },
  "scores": {
    "brand_identity": { "status": "ok", "risk": 0.9 },
    "payment":        { "status": "ok", "risk": 0.8 },
    "message":        { "status": "ok", "risk": 0.7 },
    "domain":         { "status": "ok", "risk": 0.95 },
    "number":         { "status": "ok", "risk": 0.4 }
  },
  "reason_codes": ["BRAND_CHANNEL_MISMATCH", "LOOKALIKE_DOMAIN", "PERSONAL_PAYEE", "ADVANCE_PAYMENT_REQUEST"],
  "reasons": [
    { "code": "BRAND_CHANNEL_MISMATCH", "text": "This number is not on Acme Footwear's official contact list." },
    { "code": "LOOKALIKE_DOMAIN", "text": "The website name imitates acmefootwear.com but is a different, recently registered domain." },
    { "code": "PERSONAL_PAYEE", "text": "The payment would go to a person's account, not to the company." }
  ],
  "summary": "This does not look like Acme Footwear.",
  "advice": [
    "Do not pay.",
    "Open Acme Footwear's official website or app yourself and order there.",
    "If you already paid, call 1930 and report at cybercrime.gov.in."
  ],
  "degraded": false,
  "latency_ms": 812.4,
  "disclaimer": "Automated estimate, not proof. Always confirm through the brand's official website or app."
}
```

| Field | Description |
|---|---|
| `verdict` | `MATCHES_OFFICIAL`, `UNVERIFIED`, `SUSPICIOUS`, or `LIKELY_SCAM` |
| `risk_score` | 0 to 1, higher = riskier. `null` if no scorer produced a result |
| `brand` | What was detected and whether each submitted channel matched the registry |
| `scores[*].status` | `ok`, `not_applicable` (input not provided), or `failed` (check broke or timed out) |
| `reasons` | Plain-language explanations in the requested language |
| `degraded` | `true` if any applicable check failed. A degraded result can never be `MATCHES_OFFICIAL` |

### Verdict meanings

| Verdict | Meaning |
|---|---|
| `MATCHES_OFFICIAL` | Submitted contact(s) match the brand's official registry entry and no red flags were found. Still confirm in the official app |
| `UNVERIFIED` | No red flags found but couldn't be verified. **Not** a "safe" result |
| `SUSPICIOUS` | Red flags present. Don't pay until verified through official channels |
| `LIKELY_SCAM` | Strong evidence of impersonation |

### Reason codes (initial set)

| Code | Source | Meaning |
|---|---|---|
| `BRAND_CHANNEL_MATCH` | brand | Contact matches the official list |
| `BRAND_CHANNEL_MISMATCH` | brand | Known brand, but the contact isn't official |
| `BRAND_NOT_IN_REGISTRY` | brand | Brand not covered; can't verify |
| `REGISTRY_STALE` | brand | Registry entry older than 90 days |
| `REGISTRY_UNAVAILABLE` | brand | Registry DB couldn't be read |
| `PERSONAL_PAYEE` | payment | Payee looks like a personal account for a known brand |
| `PAYEE_NAME_MISMATCH` | payment | Payee name doesn't match the brand or company |
| `PAYEE_NAME_MATCH` | payment | Payee name matches the brand's registered name |
| `UPI_PHONE_BASED` | payment | UPI ID looks like a phone number (weak signal) |
| `URGENCY_PRESSURE` | message | "Today only", "last pieces" |
| `TOO_GOOD_DISCOUNT` | message | Implausibly large discount |
| `ADVANCE_PAYMENT_REQUEST` | message | Asks for money up front outside the official checkout |
| `MOVE_TO_PERSONAL_CHAT` | message | Pushes the conversation to a personal number |
| `OTP_REQUEST` | message | Asks for an OTP |
| `REMOTE_ACCESS_REQUEST` | message | Asks to install a remote-access app |
| `ML_SCAM_LIKELY` | message | Classifier probability is high |
| `LOOKALIKE_DOMAIN` | domain | Resembles a registry brand's domain |
| `NEW_DOMAIN` | domain | Registered recently |
| `URL_SHORTENER` | domain | Hides the real destination |
| `DOMAIN_LOOKUP_FAILED` | domain | Couldn't check (degraded) |
| `NUMBER_INVALID` | number | Not a valid phone number |
| `NUMBER_REPORTED` | number | Reported by multiple users |
| `DEGRADED_MODE` | decision | One or more checks unavailable |

## `POST /v1/reports`

Report a suspicious identifier. Identifiers are stored as HMAC hashes.

```json
{ "type": "phone", "value": "+91 98765 43210", "claimed_brand": "Acme Footwear", "note": "optional" }
```

`type`: `phone`, `domain`, or `upi`. A report counts toward `NUMBER_REPORTED` only after multiple **distinct** reporters. The same reporter reporting the same item repeatedly is ignored.

Response: `202 Accepted` with `{ "status": "received" }`.

## `GET /v1/brands` and `GET /v1/brands/{slug}`

Shows what the registry knows, so users can verify the tool's claims themselves.

```json
{
  "slug": "acme-footwear",
  "name": "Acme Footwear",
  "official_domains": ["acmefootwear.com"],
  "official_phones": [],
  "payment_policy": "Pays only through the official website/app checkout.",
  "sources": [{ "url": "https://www.acmefootwear.com/contact", "verified_on": "2026-10-01" }]
}
```

## Admin endpoints

Require header `X-API-Key: <ADMIN_API_KEY>`. Create/update brand entries (a source URL and `verified_on` date are mandatory) and review reports.

## `GET /healthz` / `GET /readyz`

- `/healthz` → `200 {"status":"ok"}` when the process is up.
- `/readyz` → `200` only if the registry DB is reachable and the message model is loaded; otherwise `503`.

## Errors (RFC 9457)

Content type `application/problem+json`:

```json
{
  "type": "https://trustshop.example/problems/validation-error",
  "title": "Invalid request body",
  "status": 422,
  "detail": "Provide at least one of phone_number, message_text, urls, or payment.upi_id",
  "instance": "/v1/checks"
}
```

| Status | When |
|---|---|
| `401` / `403` | Missing or wrong admin API key |
| `404` | Unknown `check_id` or brand slug |
| `422` | Payload failed validation |
| `429` | Rate limit exceeded |
| `503` | Service not ready |

> The checks endpoint intentionally does **not** return `5xx` when one scorer fails. It returns `200` with `degraded: true` and a cautious verdict.

---

## Privacy notes for API users

- Raw message text is **not** stored by default. Only the verdict, risk score, reason codes, and HMAC-hashed identifiers are kept.
- Don't send full card numbers, passwords, or OTPs. The tool never needs them.
